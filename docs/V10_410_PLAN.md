## 2) Co-KPI chief pairing dropdown

**The feature**: For shared KPIs (e.g., PBT, NFI, Total Deposits — both Retail Banking and Commercial Banking contribute), MD should be able to:
1. Pick a single chief and cascade only to them, OR
2. Pair multiple chiefs and cascade the same bank target across them (each gets a share)

**Audit finding**: This was never built. The static MD_CLUSTERS grouping (`💼 Business Directors`, `📊 Finance & Risk`, etc.) is purely for visual organization of the scorecard — not for selecting recipients.

### v10.410 design — Co-KPI Pairing UI

In "🎯 CASCADE & ALLOCATE" tab (after consolidation):

```
For MD:
┌─────────────────────────────────────────────────────────────┐
│ KPI: PBT                          [PBT is shared by 2 chiefs]│
│                                                              │
│ ☑ Director Retail Banking  (Nicholas)                       │
│ ☑ Director Commercial Banking  (Mary)                       │
│ ☐ Chief Risk Officer                                        │
│                                                              │
│ Pairing strategy:                                            │
│ ○ Equal split    ○ By prior-year actuals    ○ Manual        │
│                                                              │
│ Total bank target: 65B    To allocate: 65B   Remaining: 0   │
└─────────────────────────────────────────────────────────────┘
```

**Data model**: 
- New file `data/kpi_ownership_map.json`:
  ```json
  {
    "PBT": {
      "primary_owners": ["Chief Retail Banking Officer", "Chief Commercial Banking Officer"],
      "secondary_owners": ["Chief Finance Officer"],
      "default_pairing": "equal_split"
    },
    "Total Deposits": {
      "primary_owners": ["Chief Retail Banking Officer", "Chief Commercial Banking Officer"],
      "default_pairing": "by_prior_year"
    }
  }
  ```

**Logic**:
- Read kpi_ownership_map for each KPI in Set team targets
- Auto-pre-select primary_owners as checked recipients
- Manager can uncheck or check secondary_owners
- Pairing strategy converts the total target into per-recipient allocations

This is **a new feature** — not just connecting unused code.
