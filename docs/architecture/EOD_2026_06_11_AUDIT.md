### 3. "CBS — option to input CIF directly, fetch info, autopopulate"

**Status:** BUG. We built the wrong UX.

User asked for: *"once someone picks an existing customer in the pipeline they have an option of inputting the cif and it fetches information about the customer and autopopulates."*

γ2 built: name-based debounced search dropdown only. **No direct CIF input.**

Evidence:

- `grep clientCif|client_cif|placeholder.*CIF` in `PipelineCreate.tsx` → zero matches
- `pickedCustomer` is captured but **never sent to the backend** (`createPipelineDeal` payload has no `client_cif` field)
- The `accountNumber` field exists but it's account number, not CIF

Resolution: δ2 work — both backend (accept `client_cif` field) and frontend (CIF input alongside name search).

---

### 4. "Pipeline remembers previously input data but not matching with the tap"

**Status:** Browser autocomplete bleeding through.

Evidence:

- `CustomerSearchInput.tsx` HAS `autoComplete="off"` on its native input ✓
- BUT the rest of `PipelineCreate.tsx` uses the `<Input>` primitive which **does not set autoComplete** — it spreads `{...rest}` so the browser's default autocomplete is active on every other field
- Browsers remember previous form submissions and offer suggestions in any text input

Resolution: δ1 — set `autoComplete="off"` as a default on the `<Input>` primitive. ~15 min, affects every form.

## Key lesson reinforced during this day's work

The β5 → β5-hotfix sequence (15 TypeScript errors slipping through because `cd ..\..` between `pnpm tsc --noEmit` and `git commit` severed exit-code propagation in the cmd `&&` chain) established a new apply-block pattern: `pushd frontend\web && pnpm tsc --noEmit && popd && echo TSC_PASSED_PROCEED_WITH_COMMIT`. The pattern is now load-bearing for frontend batches.
